# Testing Matrix: Active Inference Agent (Generative Model + EFE + Empowerment)

This document defines the concrete test specifications that must pass before the Active Inference Agent is considered production-ready. Each category maps to a test class generated by `scripts/gen_active_inference_tests.py`. Tests are written in imperative form -- implement exactly as described.

**Note on target API:** Test code examples below use the TARGET API (`reset`, `infer_state`, `plan`, `act` returning `ActionOutput` with `efe_total`, `efe_terms`, `action`). When generating actual tests against the existing codebase, adapt attribute access patterns as needed. The existing `ActiveInferenceAgent` in `brain_ai/decision/active_inference.py` uses `select_action()` and dict-based outputs. Where the target API diverges from current code, the test describes the intended behavior; the implementation must be brought into alignment before the test can pass.

**Production config reference:** `obs_dim=4096`, `state_dim=256`, `action_dim=128`, `hidden_dim=512`, `planning_horizon=8`, `num_rollouts=128`, `planner_type="cem"`. Tests use smaller dimensions (`obs_dim=32`, `state_dim=16`, `action_dim=8`, `hidden_dim=32`) for speed unless stated otherwise.

## 2. Latent Encoder Tests

The latent encoder `q(s|o)` maps observations to posterior parameters. It must produce correct shapes, support reparameterization for gradient flow, and optionally condition on workspace context.

All tests use `obs_dim=32`, `state_dim=16`, `hidden_dim=32`, `B=4`.

---

### 2a) `test_output_shape`

Verify encoder output has correct shape `(B, state_dim)` for both mu and log_var.

```python
def test_output_shape(toy_encoder, device):
    o = torch.randn(4, 32, device=device)
    mu, log_var = toy_encoder.encode(o)
    assert mu.shape == (4, 16)
    assert log_var.shape == (4, 16)
```

### 2b) `test_reparameterization`

Verify that sampling via reparameterization trick produces different samples with same parameters but gradients flow through mu/log_var.

```python
def test_reparameterization(toy_encoder, device):
    o = torch.randn(4, 32, device=device)
    mu, log_var = toy_encoder.encode(o)
    s1 = toy_encoder.sample(mu, log_var)
    s2 = toy_encoder.sample(mu, log_var)
    assert not torch.allclose(s1, s2)  # stochastic
    loss = s1.sum()
    loss.backward()
    assert mu.grad is not None  # gradients flow
```

### 2c) `test_deterministic_mu`

When `deterministic=True`, sample returns mu exactly (no noise).

### 2d) `test_with_context`

When `ctx_dim > 0`, encoder accepts context tensor and output shapes are unchanged.

### 2e) `test_without_context`

When `ctx_dim=0`, encoder works with `ctx=None`.

### 2f) `test_kl_nonneg`

KL divergence `KL(q(s|o) || N(0,1))` is non-negative for all batch elements.

### 2g) `test_gradient_flow`

Gradients from a loss on sampled states reach all encoder parameters.

### 2h) `test_fp32_output`

Output tensors are always fp32 regardless of input dtype (required for EFE precision).

## 4. Transition Model Tests

The transition model `P(s'|s,a)` predicts next-state distributions. An ensemble of K models provides uncertainty estimates. Log-variance clamping prevents divergence.

All tests use `state_dim=16`, `action_dim=8`, `hidden_dim=32`, `ensemble_size=3`, `B=4`.

---

### 4a) `test_output_shape`

Each ensemble member produces `(B, state_dim)` mu and log_var.

### 4b) `test_ensemble_disagreement`

Different ensemble members produce different predictions (not collapsed). Compute pairwise cosine similarity between member predictions; mean similarity < 0.99.

### 4c) `test_log_var_clamping`

Feed extreme inputs; verify `log_var` is within `[clamp_min, clamp_max]` (default `[-10, 2]`).

```python
def test_log_var_clamping(toy_transition, device):
    s = torch.randn(4, 16, device=device) * 100  # extreme
    a = torch.randn(4, 8, device=device) * 100
    for member_mu, member_log_var in toy_transition.predict_all(s, a):
        assert member_log_var.min() >= -10.0
        assert member_log_var.max() <= 2.0
```

### 4d) `test_deterministic_mode`

When `deterministic=True`, transition returns mean prediction (no sampling noise).

### 4e) `test_action_conditioning`

Different actions produce different next-state predictions from the same state.

### 4f) `test_gradient_flow`

Gradients from prediction loss reach all transition model parameters.

### 4g) `test_multi_step`

Roll out 5 steps autoregressively; all intermediate states are finite and have correct shape.

### 4h) `test_ensemble_size`

Model with `ensemble_size=K` has exactly K members; each member's parameter count > 0.

## 6. EFE Pure Functions Tests -- GATE (a)

EFE computation must use **pure functions** (no side effects). The three terms (pragmatic, epistemic, instrumental) must sum exactly to `efe_total` within `1e-5` tolerance. All computation in fp32.

All tests use `state_dim=16`, `obs_dim=32`, `B=4`.

---

### 6a) `test_pragmatic_pure`

`compute_pragmatic(predicted_obs, preferences)` returns `(B,)` non-negative tensor. Calling twice with same inputs produces identical output (no side effects).

### 6b) `test_epistemic_pure`

`compute_epistemic(posterior_params, prior_params)` returns `(B,)` non-negative tensor. Pure function property.

### 6c) `test_instrumental_pure`

`compute_instrumental(action_sequences, state_predictions)` returns `(B,)` tensor. Pure function property.

### 6d) `test_sum_invariant` -- GATE (a) primary

**This is the primary done-when gate.** Feed synthetic distributions with known parameters and verify:

```python
def test_sum_invariant(efe_config, device):
    """Hard invariant: |sum(efe_terms.values()) - efe_total| < 1e-5."""
    B = 8
    # ... set up synthetic predicted observations, posteriors, priors, actions ...
    result = compute_efe(predicted_obs, posterior, prior, preferences, actions, config=efe_config)

    for b in range(B):
        term_sum = sum(v[b] for v in result.efe_terms.values())
        assert abs(term_sum.item() - result.efe_total[b].item()) < 1e-5, \
            f"Batch {b}: sum={term_sum.item()}, total={result.efe_total[b].item()}"
```

### 6e) `test_sum_invariant_batch`

Same as 6d but with `B=32` and randomized inputs. Every batch element must satisfy the invariant.

### 6f) `test_closed_form_gaussian_pragmatic`

For Gaussian predicted obs and Gaussian preferences with known parameters, compute pragmatic term analytically and compare to function output. Tolerance: `atol=0.1` (Monte Carlo approximation).

### 6g) `test_closed_form_kl_epistemic`

For two known Gaussians, compute `KL(q||p)` analytically and compare to epistemic term. Tolerance: `atol=0.1`.

### 6h) `test_pragmatic_monotonicity`

Observations farther from preferences produce higher pragmatic values.

### 6i) `test_epistemic_monotonicity`

Higher posterior-prior divergence produces higher epistemic values.

### 6j) `test_instrumental_correlation`

Higher action-state mutual information correlates with lower instrumental (empowerment) EFE contribution.

### 6k) `test_fp32_precision`

Even when inputs are fp16, internal EFE computation and outputs are fp32.

### 6l) `test_gradient_independence`

Gradient through one EFE term does not affect computation of other terms (pure function isolation).

## 10. Horizon Stability Tests -- GATE (b)

EFE must remain stable across different planning horizons when `normalize_by_horizon=True`. Same observation and seed should produce consistent actions for H=3, H=5, H=7.

All tests use `state_dim=16`, `action_dim=8`, `B=4`, `N=32`.

---

### 10a) `test_normalized_efe_consistent`

**Gate (b) primary.** With normalization enabled, per-step EFE (total / H) has standard deviation < 0.5 across H=3, H=5, H=7.

```python
def test_normalized_efe_consistent(device):
    """Per-step EFE consistent across horizons with normalization."""
    agent = create_agent(normalize_by_horizon=True)
    o = torch.randn(4, 32, device=device)

    per_step_efes = []
    for H in [3, 5, 7]:
        agent.config.planner.planning_horizon = H
        result = agent.plan(o)
        per_step = result.efe_total.mean().item() / H
        per_step_efes.append(per_step)

    std = torch.tensor(per_step_efes).std().item()
    assert std < 0.5, f"Per-step EFE std={std} across horizons, expected < 0.5"
```

### 10b) `test_action_stability`

Same seed, same observation: first action from H=3 and H=7 planners should be similar (cosine similarity > 0.5).

### 10c) `test_discount_consistency`

With `discount_factor=0.99`, longer horizons have diminishing marginal contribution to total EFE.

### 10d) `test_weight_independence`

Changing `pragmatic_weight` does not affect epistemic or instrumental terms (separation of concerns).

### 10e) `test_logging_present`

Plan result includes `horizon` field matching the configured planning horizon.

### 10f) `test_normalized_vs_raw`

With normalization disabled, EFE grows roughly linearly with horizon. With normalization enabled, it stays bounded.
