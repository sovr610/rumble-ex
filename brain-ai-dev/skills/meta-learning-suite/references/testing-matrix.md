# Testing Matrix: Meta-Learning Suite (MAML/FOMAML/Reptile + MAML++ Enhancements)

Concrete test specifications for the meta-learning suite. Each category maps to a test class generated by `scripts/gen_meta_tests.py`. Tests are in imperative form -- implement exactly as described.

**Target API:** Tests use the target API (`adapt`, `meta_loss` returning `MetaOutput` with `loss`, `metrics`, `inner_logs`, `adapted_params`). Where the target API diverges from current code, the test describes intended behavior; bring the implementation into alignment before the test can pass.

**Test config:** Tests use small dimensions (`hidden_dim=32`, `input_dim=16`, `output_dim=5`, `inner_steps=3`) for speed unless stated otherwise.

## 2. TestInnerLoopEngine (~15 tests)

Three backends (`torch.func`, `higher`, custom SGD) must produce equivalent results and support second-order gradient tracking, gradient clipping, and AMP safety.

All tests use `Linear(16, 32) -> ReLU -> Linear(32, 5)`, `B=4`, `inner_steps=3`.

---

### 2a) `test_torch_func_backend_forward`

Verify `functional_call` with the `torch_func` backend produces correct logits. Extract parameters as a dict, call `functional_call(model, params, x)`. Assert output shape is `(B, 5)` and values are finite.

### 2b) `test_torch_func_inner_step`

Perform one inner-loop step using `torch_func`. Compute cross-entropy on support set, take gradient, apply SGD. Assert updated parameters differ from originals and loss decreases.

### 2c) `test_custom_sgd_backend_forward`

Same as 2a but using the custom SGD backend (`torch.autograd.grad` + manual update). Assert output shape and finiteness.

### 2d) `test_custom_sgd_inner_step`

Same as 2b but using the custom SGD backend. Verify one step updates parameters and loss decreases.

### 2e) `test_backend_equivalence`

Run the same adaptation (fixed seed, same model, same data) through `torch_func` and `custom` backends. Compare adapted parameters element-wise with `atol=1e-5`.

### 2f) `test_create_graph_true_retains_grad_fn`

Adapt with `create_graph=True`. Assert every adapted parameter tensor has a non-None `grad_fn`, confirming the computation graph is retained for second-order differentiation.

### 2g) `test_create_graph_false_no_grad_fn`

Adapt with `create_graph=False` (first-order mode). Assert adapted parameters are leaf tensors without `grad_fn`.

### 2h) `test_gradient_clipping_applied`

Create a support set that produces large gradients (scale inputs by 100). Set `inner_clip=1.0`. After one inner step, verify the gradient norm recorded in the step log is at or below 1.0 (within tolerance).

### 2i) `test_gradient_clipping_not_applied`

Use normal-scale inputs with `inner_clip=100.0` (large clip). Verify gradient norm in the step log is unchanged (no clipping occurred).

### 2j) `test_amp_safety_fp32_inner`

Wrap the outer computation in `torch.cuda.amp.autocast()`. Run inner-loop adaptation. Assert all adapted parameters are `torch.float32`, not `float16`. Requires CUDA.

### 2k) `test_step_log_schema`

Run 3 inner steps. Assert each `StepLog` entry contains fields: `loss` (scalar float), `accuracy` (float in [0,1]), `grad_norm` (non-negative float), `update_norm` (non-negative float).

### 2l) `test_multi_step_trajectory`

Run `s=5` inner steps. Assert the returned log list has exactly 5 entries, and loss is monotonically non-increasing (on the support set).

### 2m) `test_higher_backend_if_available`

Skip if `higher` is not installed. Run adaptation through the `higher` backend. Assert adapted params have correct shapes and values are finite.

### 2n) `test_auto_backend_selection`

Set `backend="auto"`. Verify the engine selects `torch_func` when `torch.func` is available (PyTorch >= 2.0). Check the returned log metadata includes `backend_used` field.

### 2o) `test_empty_support_raises`

Pass an empty support set (zero samples). Assert the engine raises `ValueError` with a message indicating zero-shot support is not valid.

## 3. TestMAML (~10 tests)

MAML computes second-order meta-gradients through the inner-loop computation graph. Adapted parameters retain `grad_fn` for backpropagation through adaptation.

All tests use the toy linear model, `inner_steps=3`, `inner_lr=0.01`.

---

### 3a) `test_maml_meta_gradient_exists`

Run MAML `meta_loss` on a single task. Call `loss.backward()`. Assert every base parameter has non-zero `.grad`.

### 3b) `test_maml_meta_gradient_vs_reference`

Toy single-layer linear model (`Linear(4, 2)`, no bias). One inner step on a single example. Hand-compute the Hessian-vector product analytically. Compare MAML meta-gradient against the analytical reference. Tolerance: `atol=1e-4`.

### 3c) `test_maml_detach_detector`

After MAML adaptation, verify adapted parameters retain `grad_fn` (second-order graph intact). This is the detach detector: if any adapted parameter is accidentally detached, the test fails.

### 3d) `test_maml_query_loss_decreases`

Run 5 meta-training steps (outer loop). Record query loss at each step. Assert final query loss is lower than initial query loss.

### 3e) `test_maml_adaptation_improves_accuracy`

Compute accuracy on query set before adaptation (using base params) and after adaptation (using adapted params). Assert `post_adapt_acc > pre_adapt_acc`.

### 3f) `test_maml_multi_task_averaging`

Create a task batch with `T=4` tasks. Run `meta_loss`. Assert the returned loss equals the mean of per-task query losses (within `atol=1e-5`). Verify by running each task individually and averaging.

### 3g) `test_maml_deterministic`

Fix seed. Run `meta_loss` three times with identical inputs. Assert all three loss values are identical (`atol=0`).

### 3h) `test_maml_inner_steps_effect`

Run MAML with `inner_steps=1` and `inner_steps=5` on the same task. Assert the 5-step variant achieves lower query loss than the 1-step variant (on a toy task where more adaptation helps).

### 3i) `test_maml_gradient_accumulation`

Run `meta_loss` with `T=4` tasks. Verify gradients on base parameters are the accumulated result of all 4 tasks (not just the last task). Check by comparing against the sum of per-task gradients divided by T.

### 3j) `test_maml_output_contract`

Verify `MetaOutput` has all required fields: `loss` (scalar tensor), `metrics` (dict with keys `pre_adapt_acc`, `post_adapt_acc`, `fast_gain`, `auac`), `inner_logs` (list of `StepLog`), `adapted_params` (dict of tensors).

## 4. TestFOMAML (~8 tests)

FOMAML drops second-order terms (`create_graph=False`). Gradients exist on base parameters but do not flow through adaptation.

---

### 4a) `test_fomaml_meta_gradient_exists`

Run FOMAML `meta_loss`. Call `loss.backward()`. Assert base parameters have non-zero `.grad`.

### 4b) `test_fomaml_no_second_order`

After FOMAML adaptation, verify adapted parameters do NOT have `grad_fn` (confirming `create_graph=False`). This is the inverse of the MAML detach detector.

### 4c) `test_fomaml_cheaper_than_maml`

Time FOMAML and MAML forward+backward on the same task (5 inner steps, same model). Assert FOMAML wall-clock time is less than MAML. Allow 20% margin for timing noise: `fomaml_time < maml_time * 1.2`.

### 4d) `test_fomaml_adaptation_works`

Compute query accuracy before and after FOMAML adaptation. Assert `post_adapt_acc > pre_adapt_acc`.

### 4e) `test_fomaml_vs_maml_step0_equal`

Before any adaptation (step 0), MAML and FOMAML produce identical predictions. Assert logits match exactly (`atol=0`), since the pre-adaptation model is the same.

### 4f) `test_fomaml_deterministic`

Same seed, same input: three FOMAML runs produce identical loss values.

### 4g) `test_fomaml_gradient_magnitude`

Compare gradient norms from FOMAML and MAML on the same task. Assert FOMAML gradient norm is within 10x of MAML gradient norm (sanity check that first-order approximation is in the right ballpark).

### 4h) `test_fomaml_output_contract`

Verify `MetaOutput` has all required fields, identical schema to MAML output.

## 5. TestReptile (~8 tests)

Reptile performs weight-space interpolation: base parameters move toward adapted parameters by factor epsilon. No query set required.

---

### 5a) `test_reptile_weight_interpolation`

After one Reptile step with `epsilon=0.1`, verify each base parameter has moved: `theta_new = theta + 0.1 * (phi - theta)`, where `phi` is the adapted parameter. Check within `atol=1e-6`.

### 5b) `test_reptile_no_query_needed`

Run Reptile with task batch that has support sets only (no query sets). Assert no error is raised and a valid `MetaOutput` is returned.

### 5c) `test_reptile_epsilon_effect`

Run Reptile with `epsilon=0.01` and `epsilon=0.5`. Assert the parameter change magnitude is proportionally larger for the bigger epsilon.

### 5d) `test_reptile_epsilon_decay`

Configure linear epsilon decay from 1.0 to 0.0 over 100 steps. At step 50, verify epsilon is approximately 0.5. At step 100, verify epsilon is approximately 0.0.

### 5e) `test_reptile_adaptation_works`

Evaluate adapted model on a held-out set. Assert post-adaptation accuracy exceeds pre-adaptation accuracy.

### 5f) `test_reptile_deterministic`

Same seed, same input: three Reptile runs produce identical adapted parameters.

### 5g) `test_reptile_multi_task`

Run Reptile over `T=4` tasks. Verify the weight delta is the average of per-task deltas `(phi_t - theta)`.

### 5h) `test_reptile_output_contract`

Verify `MetaOutput` has all required fields. Note: `inner_logs` may be empty or contain only support-set logs (no query-set logs since Reptile has no query phase).

## 6. TestMAMLPlusPlus (~12 tests)

MAML++ adds four independently toggleable enhancements: LSLR, MSL, derivative-order annealing, and BN mode control.

All tests use the toy linear model, `inner_steps=3`.

---

### 6a) `test_lslr_parameter_shape`

When `use_lslr=True`, verify LSLR parameters have shape `(num_steps, num_layers)`. For a 2-layer model with 3 inner steps, expect shape `(3, 2)`.

### 6b) `test_lslr_applied_per_layer`

After one inner step, verify different layers received different effective learning rates. Extract per-layer update magnitudes and assert they are not all identical.

### 6c) `test_lslr_applied_per_step`

Run 3 inner steps with LSLR. Verify the learning rate applied at step 0 differs from step 2 (the LSLR parameters are per-step).

### 6d) `test_lslr_clamp_bounds`

Initialize LSLR parameters to extreme values (some at -1.0, some at 100.0). After clamping, verify all effective LRs are within `[1e-6, 1.0]`.

### 6e) `test_lslr_gradients_flow`

Run MAML++ with LSLR enabled. After `meta_loss.backward()`, assert LSLR parameters have non-zero `.grad`.

### 6f) `test_msl_uniform_weights`

With `msl_weights="uniform"` and 3 inner steps, verify weights are `[1/3, 1/3, 1/3]` (summing to 1).

### 6g) `test_msl_linear_increase`

With `msl_weights="linear_increase"` and 3 inner steps, verify later steps have higher weights. Assert `w[2] > w[1] > w[0]` and weights sum to 1.

### 6h) `test_msl_learned_weights`

With `msl_weights="learned"`, run 5 meta-steps. Verify learned MSL weight parameters change from their initial values (optimizer is updating them).

### 6i) `test_msl_all_steps_contribute`

With MSL enabled, query loss is computed at each inner step (not just the final step). Verify `inner_logs` contains a `query_loss` field for each of the 3 steps.

### 6j) `test_annealing_starts_first_order`

With `use_annealing=True` and `annealing_start_epoch=10`, at epoch 5, verify the engine uses `create_graph=False` (first-order mode). Check adapted parameters have no `grad_fn`.

### 6k) `test_annealing_transitions`

At epoch 15 (past `annealing_start_epoch=10`), verify the engine uses `create_graph=True` (second-order mode). Check adapted parameters retain `grad_fn`.

### 6l) `test_bn_modes`

For each BN mode (`"transductive"`, `"per_step"`, `"frozen"`), run 3 inner steps on a model with BatchNorm layers. Assert no errors, output shapes are correct, and values are finite. Additionally verify:
- `"frozen"`: running stats are unchanged after adaptation.
- `"per_step"`: separate BN statistics exist per inner step.
- `"transductive"`: BN uses batch statistics from the current support set.

## 7. TestEpisodeSampler (~12 tests)

Deterministic few-shot episodes: N classes, K support per class, Q query per class. Splits are class-disjoint.

---

### 7a) `test_deterministic_same_seed`

Generate two episodes with identical `(global_seed=42, epoch=0, episode_idx=0)`. Assert both episodes contain exactly the same classes, support samples, and query samples (all tensors match via `torch.equal`).

### 7b) `test_deterministic_different_seed`

Generate episodes with `seed=42` and `seed=99` (same epoch and idx). Assert the episodes differ in at least one of class selection or sample selection.

### 7c) `test_n_way_correct`

Generate a 5-way episode. Assert exactly 5 unique classes appear in the support labels.

### 7d) `test_k_shot_correct`

Generate a 5-way 1-shot episode. Assert exactly 1 support example per class (5 total support samples). Repeat with 5-shot: assert exactly 5 per class (25 total).

### 7e) `test_q_query_correct`

Generate a 5-way 1-shot 15-query episode. Assert exactly 15 query examples per class (75 total query samples).

### 7f) `test_class_disjoint_splits`

Generate the full class split for a dataset. Assert no class ID appears in more than one of `{train_classes, val_classes, test_classes}`.

### 7g) `test_support_query_disjoint`

Within a single episode, assert no sample index appears in both the support set and the query set.

### 7h) `test_label_relabeling`

Assert episode labels are in `[0, N)` (contiguous integers starting from 0), not the original dataset class IDs. For a 5-way episode, unique labels should be `{0, 1, 2, 3, 4}`.

### 7i) `test_class_ids_logged`

Assert `episode.class_ids` contains the original dataset class IDs (before relabeling), allowing mapping back to the original class names.

### 7j) `test_omniglot_rotations`

Skip if Omniglot data not available. Configure Omniglot with 4 rotations (0, 90, 180, 270 degrees). Assert total class count is `1623 * 4 = 6492`.

### 7k) `test_mini_imagenet_split_sizes`

Skip if mini-ImageNet data not available. Assert train/val/test class counts are 64/16/20 respectively (Ravi & Larochelle split).

### 7l) `test_coverage_over_episodes`

Generate 500 episodes from a toy dataset with 20 classes. Assert all 20 classes appear at least once across all episodes (no class is permanently excluded by the sampling strategy).

## 8. TestMetaMetrics (~10 tests)

Track adaptation quality: per-step accuracy curves, AUAC, fast adaptation gain, gradient diagnostics.

---

### 8a) `test_adaptation_curve_shape`

Run 3 inner steps. Assert the adaptation curve has `3 + 1 = 4` points (step 0 through step 3, inclusive of the pre-adaptation point).

### 8b) `test_adaptation_curve_step0`

Assert the first point (index 0) of the adaptation curve is the pre-adaptation accuracy (evaluated on the query set before any inner-loop updates).

### 8c) `test_auac_computation`

Provide a known adaptation curve: `[0.2, 0.5, 0.7, 0.8]` (4 points). Compute AUAC via trapezoidal rule. Expected: `(0.2+0.5)/2 + (0.5+0.7)/2 + (0.7+0.8)/2 = 1.7`. Normalize by 3 intervals: `AUAC = 1.7/3 = 0.5667`. Assert within `atol=1e-4`.

### 8d) `test_fast_adaptation_gain`

Assert `fast_gain = curve[1] - curve[0]` (accuracy improvement after the first inner step).

### 8e) `test_gradient_norm_tracking`

Run 3 inner steps with gradient tracking. Assert per-step gradient norms are all positive floats.

### 8f) `test_update_norm_tracking`

Run 3 inner steps. Assert per-step update norms (norm of `params_new - params_old`) are all positive floats.

### 8g) `test_lslr_statistics`

Run with LSLR enabled. Assert metrics include `lslr_mean`, `lslr_min`, `lslr_max` as positive floats.

### 8h) `test_metrics_json_serializable`

Collect all metrics from a full `meta_loss` call. Serialize to JSON with `json.dumps()`. Assert no `TypeError` is raised (all values are JSON-compatible: float, int, str, list, dict). Round-trip through `json.loads` and verify the result is a dict.

### 8i) `test_metrics_aggregation`

Run `meta_loss` on a task batch with `T=4` tasks. Assert batch-level metrics (e.g., `post_adapt_acc`) are the mean of per-task metrics. Verify by computing per-task metrics individually.

### 8j) `test_empty_metrics_no_crash`

Pass an empty task batch (zero tasks). Assert the function returns valid metrics with zero values rather than crashing with a division-by-zero or index error.

## 9. TestCheckpoint (~10 tests)

Preserve model weights, inner-loop hyperparameters, MAML++ state, RNG state, and sampler config for full reproducibility.

---

### 9a) `test_save_load_round_trip`

Save a checkpoint to a temporary file. Load it back. Compare every tensor in `state_dict` against the original via `torch.equal`.

### 9b) `test_checkpoint_includes_hyperparams`

Load a saved checkpoint. Assert the checkpoint dict contains keys: `algo`, `inner_steps`, `inner_lr`, `inner_clip`, `second_order`.

### 9c) `test_checkpoint_includes_lslr`

Save a checkpoint with LSLR enabled. Load and verify `lslr_state_dict` is present and has the correct shape `(num_steps, num_layers)`.

### 9d) `test_checkpoint_includes_msl_weights`

Save a checkpoint with MSL enabled and `msl_weights="learned"`. Load and verify `msl_weights` tensor is present.

### 9e) `test_checkpoint_includes_rng_state`

Save a checkpoint with `save_rng_state=True`. Load and verify the checkpoint contains `rng_state` with keys for Python, NumPy, and PyTorch random states.

### 9f) `test_checkpoint_includes_sampler_config`

Save a checkpoint with `save_sampler_config=True`. Load and verify `episode_config` is present with fields `n_way`, `k_shot`, `q_query`, `dataset`.

### 9g) `test_cross_device_load`

Save a checkpoint on CPU. Load with `map_location="cpu"`. Assert all tensors are on CPU and values are correct. If CUDA is available, also save on CUDA and load on CPU.

### 9h) `test_version_validation`

Modify the `version` field in a saved checkpoint to an incompatible version string. Assert loading raises a clear error message mentioning version incompatibility.

### 9i) `test_hyperparameter_diff`

Save two checkpoints with different `inner_lr` values. Use the diff utility to compare them. Assert the diff output identifies `inner_lr` as changed and reports old and new values.

### 9j) `test_eval_checkpoint_minimal`

Save an eval-only checkpoint (minimal format). Assert it contains only `state_dict` and `inner_config` (no LSLR, no MSL, no RNG, no sampler config). Assert it is smaller than the full checkpoint.

## 10. TestPhase7Runner (~8 tests)

Orchestrate the full meta-training loop: build task distribution, run meta-epochs, log metrics, save checkpoints. Supports dev mode (CPU) and production mode (GPU).

---

### 10a) `test_build_task_distribution`

Call `build_task_distribution(config)` with a dev config. Assert the returned sampler has the correct `n_way`, `k_shot`, and `q_query` from the config.

### 10b) `test_run_meta_epoch_no_crash`

Run one meta-epoch with dev config (50 episodes, 1 inner step, CPU). Assert no exceptions are raised.

### 10c) `test_run_meta_epoch_loss_decreases`

Run 3 meta-epochs. Record mean loss per epoch. Assert `loss[epoch_2] < loss[epoch_0]`.

### 10d) `test_run_meta_epoch_metrics_produced`

Run one epoch. Assert the returned metrics dict contains keys: `mean_loss`, `mean_pre_acc`, `mean_post_acc`, `mean_auac`, `mean_fast_gain`.

### 10e) `test_dev_mode_cpu_only`

Configure dev mode with `device="cpu"`. Run one epoch. Assert no CUDA operations are attempted (all tensors are on CPU).

### 10f) `test_dev_mode_fast`

Mark `@pytest.mark.slow`. Run the full dev-mode pipeline (50 episodes, Conv4, 3 inner steps). Assert total wall-clock time is under 60 seconds.

### 10g) `test_evaluation_adaptation_curves`

After training, run evaluation. Assert the evaluation output includes a per-step accuracy curve with `inner_steps + 1` points, and `post_adapt_acc > pre_adapt_acc`.

### 10h) `test_metrics_json_output`

Run one epoch with `output_dir` set to a temp directory. Assert a `metrics.json` file is written containing valid JSON with all expected keys.

### Skip Conditions

| Decorator | Reason |
|---|---|
| `@pytest.mark.skipif(not HAS_HIGHER, reason="higher not installed")` | Tests requiring the `higher` library |
| `@pytest.mark.skipif(not HAS_TORCH_FUNC, reason="torch.func not available")` | Tests requiring PyTorch >= 2.0 functional API |
| `@pytest.mark.skipif(not torch.cuda.is_available(), reason="CUDA required")` | Tests requiring GPU (AMP safety, cross-device) |
| `@pytest.mark.skipif(not OMNIGLOT_AVAILABLE, reason="Omniglot data not found")` | Tests using real Omniglot dataset |
| `@pytest.mark.skipif(not MINI_IMAGENET_AVAILABLE, reason="mini-ImageNet data not found")` | Tests using real mini-ImageNet dataset |

### Marks

| Mark | Purpose |
|---|---|
| `@pytest.mark.slow` | Tests that take > 10 seconds (dev mode timing, multi-epoch convergence) |
| `@pytest.mark.gpu` | Tests that require CUDA |
| `@pytest.mark.benchmark` | Performance comparison tests (FOMAML vs MAML timing) |

### Assertion Patterns

| Pattern | Code |
|---|---|
| Gradient existence | `assert param.grad is not None and param.grad.abs().sum() > 0` |
| grad_fn retention | `assert adapted_params[key].grad_fn is not None` |
| grad_fn absence | `assert adapted_params[key].grad_fn is None` |
| Determinism | `assert torch.allclose(result1, result2, atol=0)` |
| Adaptation improvement | `assert post_acc > pre_acc` |
| AUAC positive | `assert auac > 0.0` |
| JSON serialization | `json.dumps(metrics)` -- must not raise `TypeError` |
| Finite values | `assert torch.isfinite(tensor).all()` |
| Shape checks | `assert tensor.shape == expected_shape` |
