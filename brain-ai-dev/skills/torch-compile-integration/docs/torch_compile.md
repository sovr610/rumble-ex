## Quick Start

```python
from compile_config_template import CompileConfig, fast_dev_config
from compile_wrap_template import maybe_compile
import logging

# 1. Create a config (disabled by default — opt-in explicitly)
cfg = CompileConfig(
    enabled=True,
    mode="default",          # start here
    healthcheck=True,        # run smoketest before committing
    fail_policy="fallback_eager",  # never crash
)

# 2. Compile your model safely
logger = logging.getLogger(__name__)
model = maybe_compile(model, cfg, logger, sample_batch=your_batch)

# 3. Train as normal — the compiled model is a drop-in replacement
for batch in dataloader:
    output = model(**batch)
    loss = loss_fn(output, batch)
    loss.backward()
    optimizer.step()
    optimizer.zero_grad()
```

**Key principle**: `maybe_compile` never crashes. On any failure, it logs
the error and returns your original model unchanged.

## When to Use Each Mode

### Mode Selection Guide

```
Start: mode="default"
  → Profile 100 steps
  → Is Python CPU overhead dominating GPU time? (TORCH_LOGS=perf_hints)
      Yes → Are all input shapes fixed?
                Yes: mode="reduce-overhead"
                No:  Use bucketing + stay on "default"
      No  → Is this a long production run (>1000 GPU-hours)?
                Yes: mode="max-autotune"
                No:  Stay on "default"
```

### Mode Comparison Table

| Mode | Compile Time | Speedup | CUDA Graphs | Shape Requirement | Use When |
|------|-------------|---------|-------------|-------------------|----------|
| `default` | Seconds | 1.3–2x | No | Variable OK | Development, first attempt |
| `reduce-overhead` | Seconds | 1.5–2.5x | Yes | Fixed shapes needed | Inference serving, fixed shapes |
| `max-autotune` | Minutes | 1.5–3x | Yes | Fixed shapes needed | Long production training |
| `max-autotune-no-cudagraphs` | Minutes | 1.4–2.5x | No | Variable OK | Long runs, variable shapes |

### Mode: `default`

**Use for**:
- Your first compilation attempt — always start here.
- Workloads with variable sequence lengths (doesn't require CUDA graphs).
- Quick development iteration (compiles in seconds, not minutes).

**Typical config**:
```python
cfg = CompileConfig(
    enabled=True,
    mode="default",
    options={"shape_padding": True, "epilogue_fusion": True},
)
```

### Mode: `reduce-overhead`

**Use for**:
- Fixed-shape inference serving where Python overhead dominates.
- Training with drop_last=True and fixed batch sizes.
- When TORCH_LOGS=perf_hints shows CUDA graphs are applicable.

**Requirements**:
- Static shapes within the compiled region (no shape variation).
- No CPU-GPU sync points in the compiled region (no `.item()`, no `print(tensor)`).
- No dynamic control flow based on tensor values.

**Typical config**:
```python
cfg = CompileConfig(
    enabled=True,
    mode="reduce-overhead",
    dynamic=False,  # enforce static shapes
    options={"shape_padding": True},
)
```

### Mode: `max-autotune`

**Use for**:
- Production training runs where compilation time amortizes.
- After validating correctness with `default` mode.
- When you've confirmed shape stability (no recompile warnings in logs).

**Compilation caching**:
Inductor caches compiled kernels to `~/.cache/torch/inductor/`. Second run
with same model is fast. For fresh benchmarks, clear the cache:
```bash
rm -rf ~/.cache/torch/inductor/
```

**Typical config**:
```python
cfg = CompileConfig(
    enabled=True,
    mode="max-autotune",
    dynamic=None,  # auto-generalize on first shape change
    options={"shape_padding": True, "epilogue_fusion": True},
    healthcheck=True,
    smoketest_steps=5,
)
```

### Backend: `aot_eager` (Debugging Only)

Runs AOTAutograd without code generation. Use to isolate whether a bug
is in Dynamo (tracing) vs Inductor (codegen):

```python
# Test 1: Does aot_eager work?
cfg_aot = CompileConfig(enabled=True, mode="default", backend="aot_eager")
compiled_aot = maybe_compile(model, cfg_aot, logger, sample_batch)

# Test 2: Does inductor fail?
cfg_ind = CompileConfig(enabled=True, mode="default", backend="inductor")
compiled_ind = maybe_compile(model, cfg_ind, logger, sample_batch)
```

If aot_eager works but inductor fails → bug is in Inductor. File bug with
`TORCH_LOGS=output_code` output attached.

## The Safe Wrapper Pattern

`maybe_compile` is the **single entry point** for all compilation. Never
call `torch.compile()` directly in training code.

### Why This Matters

- Training runs take hours or days. A compile failure at step 0 must not
  waste that compute.
- Compilation failures can be subtle — they appear as Triton errors, graph
  break limits being exceeded, or CUDA memory issues. These must be caught.
- The smoketest catches failures that don't show up until the first backward.

### Execution Flow

```
maybe_compile(model, cfg, logger, sample_batch)
  │
  ├── cfg.enabled = False? → return model unchanged
  │
  ├── Apply blocklist (torch.compiler.disable on matching submodules)
  │
  ├── cfg.allowlist non-empty?
  │     Yes → compile only matching submodules
  │     No  → torch.compile(model, mode, backend, dynamic, fullgraph, options)
  │
  ├── torch.compile raises?
  │     fail_policy="fallback_eager" → log + return original model
  │     fail_policy="raise"          → re-raise
  │
  ├── cfg.healthcheck=True and sample_batch provided?
  │     → Run smoketest_steps forward-backward cycles
  │     → Any failure: log + apply fail_policy
  │
  └── Return compiled model
```

### When fail_policy="raise" Is Appropriate

Use `fail_policy="raise"` only in:
- CI/CD validation gates where you need to catch regressions.
- Integration tests that explicitly verify compilation works.
- Debugging sessions where you want the full traceback.

Never use in production training scripts.

### Smoketest Health Check

The smoketest runs `smoketest_steps` (default 3) complete training steps:
```
for step in range(smoketest_steps):
    optimizer.zero_grad()
    output = model(**batch)
    loss = loss_fn(output, batch)
    if isnan(loss): return False
    loss.backward()
    if any gradient is non-finite: return False
    optimizer.step()
return True
```

The **first step triggers JIT compilation**. If compilation takes 30 seconds,
the smoketest will take at least 30 seconds on the first run. This is expected.

## Shape Management Playbook

### The Recompile Problem

Every unique input shape causes a recompile. With variable-length NLP data:
- 100 unique sequence lengths = 100 recompiles = 100x compilation overhead.
- After 8 recompiles, Dynamo gives up on that function and runs it in eager.

### Strategy 1: Bucketing (Recommended for LLM Training)

Group sequences into fixed buckets. Only `len(buckets)` shapes ever appear.

```python
from shape_stabilize_template import ShapeStabilizer, collate_fn_with_bucketing
from functools import partial

# Option A: Manual use in training loop
stabilizer = ShapeStabilizer(buckets=[256, 512, 1024, 2048], pad_token_id=0)

for batch in raw_dataloader:
    # Pad to bucket boundary before model call
    input_ids = stabilizer.bucket_batch(batch["input_ids"])
    attention_mask = stabilizer.make_attention_mask(input_ids)
    output = compiled_model(input_ids=input_ids, attention_mask=attention_mask)

# Option B: DataLoader collate_fn (cleaner)
collate = partial(collate_fn_with_bucketing,
                  buckets=[256, 512, 1024, 2048],
                  pad_token_id=tokenizer.pad_token_id)
dataloader = DataLoader(dataset, batch_size=16, collate_fn=collate)
```

**Choosing bucket sizes**:
- Analyze your dataset's sequence length distribution.
- Place bucket boundaries at natural percentiles (e.g., p50, p75, p90, p99).
- Default [256, 512, 1024, 2048] works for most LLM pretraining datasets.
- Longer sequences (4096, 8192) may need additional buckets.

### Strategy 2: Automatic Dynamic Shapes (dynamic=None)

Default behavior. Dynamo starts static, auto-generalizes on first shape mismatch.

```python
cfg = CompileConfig(enabled=True, mode="default", dynamic=None)
```

**Works well for**: Workloads with a small number of unique shapes (< 8).
**Breaks down for**: Highly variable lengths (each batch different → 8+ recompiles → fallback to eager).

### Strategy 3: mark_dynamic (Advanced)

Pre-declare which dimensions vary before the first compiled call.

```python
import torch._dynamo

# Call BEFORE each compiled model invocation (not inside forward())
torch._dynamo.mark_dynamic(input_ids, dim=1, min=1, max=2048)
torch._dynamo.mark_dynamic(attention_mask, dim=1, min=1, max=2048)

output = compiled_model(input_ids=input_ids, attention_mask=attention_mask)
```

**When to use**: When you can't use bucketing (e.g., custom data pipeline)
and want more control than dynamic=None.

### Anti-Pattern: `dynamic=True`

```python
# DO NOT USE in production
cfg = CompileConfig(dynamic=True)  # generates slower kernels
```

`dynamic=True` forces every dimension symbolic, generating highly generic
(slow) kernels. PyTorch docs call this "not recommended" / "testing-oriented".

### Verifying Shape Stability

```bash
# Watch for recompile triggers during training
TORCH_LOGS=recompiles python train.py 2>&1 | grep -E "(Recompiling|recompile)"

# Expect: 4 recompiles at startup (one per bucket), then silence
# Red flag: recompiles every N steps (shape instability)
```

## Debugging Steps

### Step 1: Verify Compilation Is Happening

```bash
TORCH_LOGS=recompiles python train.py 2>&1 | head -20
```

Look for: `[recompiles] Compiling function forward in model.py:...`
If absent: compilation was disabled or failed silently before logging.

### Step 2: Count Graph Breaks

```bash
TORCH_LOGS=graph_breaks python -c "
import torch, your_model
model = torch.compile(your_model, mode='default')
model(sample_input)
" 2>&1 | grep -c "graph_break"
```

Goal: 0 graph breaks. Each break reduces optimization opportunity.

Find locations:
```bash
TORCH_LOGS=graph_breaks python train.py 2>&1 | grep graph_break
```

### Step 3: Diagnose Graph Breaks

```python
# Option A: fullgraph=True raises on first break
model = torch.compile(model, fullgraph=True)
try:
    model(sample_input)
except torch._dynamo.exc.Unsupported as e:
    print(f"Graph break at: {e}")

# Option B: explain() gives full analysis
explanation = torch._dynamo.explain(model)(sample_input)
print(f"Number of graphs: {len(explanation.graphs)}")
for reason in explanation.graph_break_reasons:
    print(f"Break: {reason}")
```

### Step 4: Fix Graph Breaks

| Break Cause | Fix |
|-------------|-----|
| `print(tensor)` | Move print outside compiled region or use `@torch.compiler.disable` |
| `.item()` in control flow | Rewrite as masked operations |
| Custom Python class | Use `@torch.compiler.disable` on the method |
| Unsupported op | Use `@torch.compiler.disable` or file a bug |
| `for i in range(tensor):` | Replace with tensor operations |

```python
# Fix: use @torch.compiler.disable
@torch.compiler.disable
def log_activations(x):
    print(f"Mean: {x.mean().item():.4f}")
    return x

# In forward:
# h = log_activations(h)  # this line won't be compiled
```

### Step 5: Check Shape Stability

```bash
TORCH_LOGS=recompiles,dynamic python train.py 2>&1 | head -100
```

Healthy output: `[recompiles] Compiling ...` appears once per bucket shape, then stops.
Unhealthy output: `[recompiles] Recompiling due to tensor size mismatch` appears every step.

Fix: Enable bucketing (see Shape Management section).

### Step 6: Diagnose CUDA Graph Issues

```bash
TORCH_LOGS=perf_hints python train.py 2>&1 | grep -E "(graph|CUDA)"
```

Look for:
- `Capturing CUDA graph` — CUDA graphs are working.
- `Unable to capture CUDA graph due to: ...` — explains the blocker.

Common blockers:
- `.item()` inside forward: causes CPU-GPU sync.
- Logging tensor values: `print(loss.item())` breaks capture.
- `F.dropout` with `training=True` and random state: use `torch.backends.cudnn.benchmark = True`.

### Step 7: Compare Eager vs Compiled Output

```python
torch.manual_seed(42)
model_eager = YourModel()
x = torch.randn(4, 128)
eager_out = model_eager(x).detach()

torch.manual_seed(42)
model_compiled = YourModel()
model_compiled.load_state_dict(model_eager.state_dict())
compiled = torch.compile(model_compiled, mode="default")
compiled_out = compiled(x).detach()

max_diff = (eager_out - compiled_out).abs().max()
print(f"Max difference: {max_diff}")
assert torch.allclose(eager_out, compiled_out, atol=1e-3), "Numerical mismatch!"
```

## Common Gotchas and Fixes

### Gotcha 1: First Step Is Slow (It's Supposed To Be)

**Symptom**: Step 1 takes 30+ seconds. Steps 2+ are fast.

**Explanation**: JIT compilation happens on the first forward pass. This is
normal. The first step measures compile time, not runtime.

**Fix**: Always warm up before benchmarking.
```python
for _ in range(warmup_steps):  # warmup >= 10, ideally 50
    model(sample)
# NOW benchmark
```

### Gotcha 2: torch._dynamo Cache Limit Exceeded

**Symptom**: Warning: `torch._dynamo hit cache limit (8) for function ...`
Training continues but in eager mode for that function.

**Cause**: More than 8 unique shapes (or other guard conditions) for a
single function call site.

**Fix**:
- Enable bucketing to limit shapes to <= 8.
- Or increase the limit (not preferred):
```python
import torch._dynamo
torch._dynamo.config.cache_size_limit = 16
```

### Gotcha 3: CUDA OOM Under reduce-overhead Mode

**Symptom**: CUDA out of memory when using `reduce-overhead` but not `default`.

**Cause**: CUDA graphs allocate static memory for all intermediates. This
is more than the dynamic allocations in eager mode.

**Fix**:
- Reduce batch size to accommodate the memory overhead.
- Use `max-autotune-no-cudagraphs` if memory is the bottleneck.
- Or stay on `default` mode.

### Gotcha 4: Gradient Mismatch with FSDP

**Symptom**: Loss diverges or gradients are wrong with FSDP + compile.

**Fix**: Wrap inner transformer blocks individually, not the full FSDP model:
```python
for block in model.transformer.blocks:
    block.forward = torch.compile(block.forward, mode="default")
```

### Gotcha 5: Checkpoint Load Fails After Compile

**Symptom**: `model.load_state_dict()` raises errors after `torch.compile`.

**Cause**: Compiled model's state dict structure may differ.

**Fix**: Load state dict before compiling.
```python
model.load_state_dict(checkpoint)  # load BEFORE compile
model = torch.compile(model, mode="default")
```

For distributed (FSDP), disable compilation before checkpointing:
```python
@torch.compiler.disable
def load_checkpoint(model, path):
    state = torch.load(path)
    model.load_state_dict(state)
```

### Gotcha 6: Data-Dependent Control Flow

**Symptom**: Graph break or `Unsupported` error on `if tensor_val > 0:`.

**Explanation**: torch.compile can't trace data-dependent conditionals because
the compiled graph is shape-specialized, not value-specialized.

**Fix**: Replace with masked operations:
```python
# Bad (causes graph break)
if attn_weights.max() > 1.0:
    attn_weights = attn_weights / attn_weights.max()

# Good (no graph break)
scale = torch.where(attn_weights.max() > 1.0, attn_weights.max(),
                    torch.ones(1, device=attn_weights.device))
attn_weights = attn_weights / scale
```

### Gotcha 7: Recompile Every Step in AMP

**Symptom**: `recompiles` log shows new compilation every step when using
`torch.cuda.amp.GradScaler`.

**Cause**: `GradScaler` may introduce shape changes from gradient unscaling.

**Fix**: Compile only the model forward-backward, not the full training step
including scaler operations. Or use `torch.amp.autocast` without GradScaler.

### Gotcha 8: Non-Finite Gradients After Compile

**Symptom**: Gradient clipping logs show `inf` gradient norms after compilation.

**Fix**: Verify with the CompileSmoketest's gradient checking. Common cause
is precision change from fused kernels. Try adding `options={"fallback_random": True}`
or switching to `backend="aot_eager"` to isolate.

## DDP/FSDP Integration Checklist

### DDP + torch.compile

Checklist before using in production:

- [ ] **Wrapping order**: `model = torch.compile(model)` BEFORE `DistributedDataParallel(model, ...)`
- [ ] **Smoketest in distributed mode**: Run `validate_compile.py` with `torchrun --nproc_per_node=2`
- [ ] **Graph breaks audit**: `TORCH_LOGS=graph_breaks` shows no DDP-specific breaks
- [ ] **Shape stability**: `TORCH_LOGS=recompiles` shows no recompiles after initial bucket compilations
- [ ] **Gradient correctness**: Compare gradient norms between eager and compiled for 10 steps
- [ ] **Checkpoint compatibility**: Verify save/load works with `@torch.compiler.disable` on save functions
- [ ] **Memory check**: Peak memory on all ranks fits within GPU memory budget

**Minimal DDP + compile setup**:
```python
import torch
import torch.distributed as dist
from torch.nn.parallel import DistributedDataParallel

dist.init_process_group("nccl")
local_rank = int(os.environ["LOCAL_RANK"])

model = YourModel().to(local_rank)

# Step 1: Compile FIRST
model = torch.compile(model, mode="default")

# Step 2: Wrap with DDP AFTER
model = DistributedDataParallel(
    model,
    device_ids=[local_rank],
    static_graph=True,  # helps if graph is fixed
)
```

### FSDP2 + torch.compile

```python
from torch.distributed._composable.fsdp import fully_shard, MixedPrecisionPolicy

mp = MixedPrecisionPolicy(param_dtype=torch.bfloat16, reduce_dtype=torch.float32)

# Shard at block level
for block in model.transformer.blocks:
    fully_shard(block, mp_policy=mp)
fully_shard(model, mp_policy=mp)

# Compile AFTER FSDP2 wrapping
model = torch.compile(model, mode="default")
```

### Selective Block Compilation (Fallback Strategy)

When full-model compile fails with DDP/FSDP:

```python
# Compile only inner blocks — avoids distributed wrapper interaction
for i, block in enumerate(model.transformer.blocks):
    model.transformer.blocks[i] = torch.compile(block, mode="default")

# Optional: compile embedding and output head too
if hasattr(model, 'embed_tokens'):
    model.embed_tokens = torch.compile(model.embed_tokens, mode="default")

# Then wrap with DDP/FSDP as normal
model = DistributedDataParallel(model, device_ids=[local_rank])
```

**Trade-off**: Python overhead at each block boundary. Can't fuse across
blocks. Still captures most compute (attention + MLP).

## Configuration Quick Reference

### CompileConfig Fields

```python
@dataclass
class CompileConfig:
    enabled: bool = False              # Master switch. Opt-in.
    mode: str = "default"             # "default" | "reduce-overhead" |
                                       # "max-autotune" | "max-autotune-no-cudagraphs"
    dynamic: Optional[bool] = None    # None=auto | False=static | True=force-dynamic(avoid)
    backend: str = "inductor"         # "inductor" | "aot_eager" | "cudagraphs"
    fullgraph: bool = False           # Raise on graph breaks instead of segmenting
    options: Optional[Dict] = None    # TorchInductor options dict
    allowlist: List[str] = ()         # Submodule names to compile (empty=all)
    blocklist: List[str] = ()         # Submodule names to skip (torch.compiler.disable)
    healthcheck: bool = True          # Run smoketest after compile
    fail_policy: str = "fallback_eager"  # "fallback_eager" | "raise"
    smoketest_steps: int = 3          # Steps in healthcheck smoketest
```

### Common `options` Dict Values

```python
options = {
    "epilogue_fusion": True,    # Fuse pointwise ops into reduction kernels
    "shape_padding": True,      # Pad shapes to GPU-alignment multiples
    "fallback_random": False,   # Use fallback for random ops (set True if issues)
    "max_autotune_gemm": True,  # Autotune GEMMs (max-autotune only)
}
```

### Pre-built Config Presets

```python
from compile_config_template import (
    default_config,      # disabled, mode="default"
    fast_dev_config,     # enabled, mode="default", fallback_eager
    production_config,   # enabled, mode="max-autotune"
```

## Decision Tree

```
Am I adding torch.compile for the first time?
└── Yes: Use CompileConfig(enabled=True, mode="default", healthcheck=True)
         Run validate_compile.py to verify all gates pass.

My model has variable sequence lengths?
├── Yes: Use ShapeStabilizer + bucketing in DataLoader collate_fn.
│        Set dynamic=None (default).
└── No:  Set dynamic=False for maximum static specialization.

I'm getting recompile warnings every step?
└── Fix: Enable bucketing. Check TORCH_LOGS=recompiles to find cause.

I have graph breaks?
├── Find them: TORCH_LOGS=graph_breaks or fullgraph=True
├── Fix them: @torch.compiler.disable on problem functions
└── Can't fix: Add to blocklist in CompileConfig

Training with DDP?
├── Compile BEFORE DistributedDataParallel wrap.
├── Test with torchrun --nproc_per_node=2 validate_compile.py
└── If compile fails with DDP: use selective block compilation.

Training with FSDP?
├── Use FSDP2 (torch.distributed._composable.fsdp) for better support.
├── If FSDP1: compile inner blocks before wrapping.
└── Always: @torch.compiler.disable on checkpoint save/load functions.

Want maximum throughput for production?
├── Validate correctness: mode="default" + compare output to eager.
├── Check shape stability: TORCH_LOGS=recompiles for 100 steps.
└── Switch to: mode="max-autotune" (or max-autotune-no-cudagraphs if variable shapes).

Something is wrong (NaN, crash, wrong output)?
├── Step 1: Disable compile (cfg.enabled=False). Still broken? → Not a compile bug.
├── Step 2: backend="aot_eager". Still broken? → Bug in Dynamo, not Inductor.
├── Step 3: TORCH_LOGS=graph_breaks. Unexpected graph breaks?
└── Step 4: Compare eager vs compiled output: torch.allclose(eager_out, compiled_out)
```
